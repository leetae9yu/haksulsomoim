# 조원안 결에 맞춘 제품 중심 발표 구조

## 1. 방향 전환

기존 발표는 법률·기술 검증을 전면에 두어 “서비스가 왜 위험한가”가 중심처럼 보였다.
수정 발표는 조원 자료의 질문인 **“소액사기 피해자가 실제로 어떤 서비스를 사용하게 되는가”**를 중심에 둔다.

새 발표의 기본 흐름은 다음과 같다.

> 피해 발생 → 정보 1회 입력 → 사건 단계 추적 → 형사·민사 트랙 분기 → 증거·서류 준비 → 강제집행 후속 관리

기존 조사 결과는 별도 법률 강의로 제시하지 않는다. 각 제품 기능을 설명할 때 그 기능이 필요한 이유,
가능한 범위, 금지되는 자동화를 뒷받침하는 **검증 레이어**로 사용한다.

## 2. 두 자료의 통합 원칙

| 조원 자료의 제품 아이디어 | 기존 조사에서 붙일 근거 | 발표에서 사용할 안전한 표현 |
|---|---|---|
| 피해 정보 1회 입력 | 8개 범주의 Intake 스키마 | 최초 입력한 사실과 증거를 이후 단계에서 재사용 |
| KICS 문자 해석 | 9단계 상태 머신, 공공 Handoff | 사용자가 붙여넣은 공식 통지에서 사건번호·기관·단계를 추출하고 직접 확인 |
| 배상명령 트랙 | 배상명령의 신청 시기·요건·한계 | 형사재판 진행 여부와 공식 통지를 기준으로 신청 가능 절차를 안내 |
| 민사 지급명령 트랙 | 지급명령의 송달·이의·본안 전환 | 민사 경로의 요건과 비용을 안내하고 공공 서식으로 연결 |
| 원클릭 트랙 피봇 | 상태 머신의 `Objection or Fallback` | 저장된 사실·증거를 유지한 채 다음 절차 준비 화면으로 전환 |
| 증거 번호 매김·PDF 출력 | Evidence Dossier, OCR, SHA-256, Provenance | 원본을 보존하고 사용자가 확인한 증거 목록과 제출용 사본을 생성 |
| 강제집행 대시보드 | 재산명시·재산조회·압류·추심 조사 | 집행권원 확보 후 별도로 필요한 회수 절차와 상태를 관리 |
| 법률 판단 금지 | 변호사법 제109조, 인간 승인 | 사기 성립·승소·회수 여부는 판단하지 않고 사실 정리와 일반 절차 안내만 제공 |

## 3. 수정 발표의 한 문장

> 소액사기 피해자가 한 번 입력한 사건 정보와 증거를 바탕으로 형사 신고부터 배상명령,
> 민사 절차, 강제집행까지 다음 행동을 놓치지 않도록 돕는 사용자 통제형 AI 리걸테크 서비스

기존의 “증거·절차 내비게이터”라는 명칭은 유지할 수 있지만, 첫 설명부터 위 사용자 경험을 제시한다.
`Evidence Dossier`, `Provenance`, `Handoff` 같은 용어는 기능을 설명한 뒤 보조 개념으로 사용한다.

| 9 | Track B. 별도 민사 절차가 필요할 수 있다 | 지급명령·소액소송의 차이, 피고 주소·송달·이의신청 조건 | 민사소송·송달 Ladder [S060–S061, S084–S085, S101] | 지급명령과 소액소송 비교 |
| 10 | 기존 정보를 버리지 않고 민사 트랙으로 전환한다 | 피해 사실과 증거를 유지한 채 필요한 항목만 추가하고 다음 절차로 이동 | `Objection or Fallback` 상태 | 전환 전후 데이터 재사용 도식 |
| 11 | 증거와 제출 자료를 한 묶음으로 정리한다 | 이체확인증·대화 내역에 목록 번호를 붙이고 사용자가 승인한 PDF 사본 생성 | OCR, 증거 계보, Neutral Export [S063–S069] | 증거 Dossier 미리보기 |
| 12 | 판결을 받아도 회수 절차는 끝나지 않는다 | 집행권원 이후 재산명시·조회·압류·추심을 별도로 추적 | 민사집행 절차 [S003–S005, S032–S040, S042–S044] | 강제집행 대시보드 |
| 13 | AI가 대신 판단하거나 제출하지는 않는다 | 승소 확률·사기 확정·완성 법률문서·대리 제출 금지, 핵심 필드 100% 확인 | 변호사법·인간 승인 [S089–S094] | 허용 / 확인 필요 / 금지 |
| 14 | 구현은 가장 안전한 기능부터 시작한다 | 1차: 입력·증거정리, 2차: 상태 추적, 3차: 공공 양식 연결, 4차: 전문가 검증 | Phase 0–4 로드맵 | MVP 단계별 확장 |
| 15 | 목표는 자동 소송이 아니라 절차 이탈 방지다 | 사용자가 자신의 사건과 증거를 통제하면서 다음 행동을 놓치지 않게 하는 서비스 | 연구 결론과 한계 | 처음의 끊어진 여정이 연결된 모습 |

## 5. 슬라이드별 말하기 중심

### 1–3장: 문제보다 제품을 먼저 이해시킨다

- 첫 장에서 법률 규제나 연구 방법론을 설명하지 않는다.
- 피해자가 서비스에서 무엇을 하는지 4단계로 즉시 보여준다.
- 통계 `100,539건`은 필요하면 2장의 작은 근거로만 사용한다. 별도 통계 슬라이드로 발표 흐름을 끊지 않는다.

### 4–6장: 조원안의 차별점인 사건 추적 경험을 구체화한다

- 최초 입력값이 이후 배상명령·민사·집행 단계에서 재사용되는 경험을 강조한다.
- “KICS 연동”이라고 표현하지 않고 **“사용자가 공식 통지를 붙여넣는다”**고 설명한다.
- 추출된 법원명·사건번호·기일은 자동 확정하지 않고 원문과 나란히 보여준 뒤 사용자가 확인한다.

### 7–10장: 형사·민사 투트랙과 전환 경험을 중심에 둔다

- 배상명령과 지급명령을 법률 강의처럼 나열하지 않는다.
- “현재 상황에서 다음에 준비할 것은 무엇인가”라는 제품 화면 관점으로 설명한다.
- “원클릭 전환”은 법적 절차의 자동 전환이 아니라 **기존 데이터의 재사용과 준비 화면 이동**을 뜻한다.

### 11–12장: 서비스가 실제로 남기는 결과물을 보여준다

- 결과물은 AI가 작성한 완성 소장이 아니라 사용자가 확인한 사실표, 증거 목록, 원본 사본, 절차 체크리스트다.
- 집행권원 확보와 실제 회수를 분리하여 강제집행 단계까지 추적하는 것이 일반 서류 생성 서비스와의 차별점이다.

### 13–15장: 안전장치는 마지막에 짧고 강하게 설명한다

- 변호사법과 개인정보보호법을 각각 독립된 강의 슬라이드로 길게 다루지 않는다.
- 조원 자료에 이미 포함된 “AI가 절대 하지 말아야 할 행동”을 한 장으로 정제한다.
- 결론은 “법률 위험 때문에 기능을 줄였다”가 아니라 “사용자가 끝까지 직접 통제할 수 있도록 설계했다”로 마무리한다.

## 6. 반드시 수정할 조원안 표현

| 기존 표현 | 수정 표현 |
|---|---|
| KICS 사건번호 연동 | 사용자가 붙여넣은 공식 통지에서 사건 정보를 추출 |
| 관할 재판부 지정 | 공식 통지에 기재된 법원·재판부를 추출하고 사용자 확인 |
| 배상명령·지급명령 신청서 자동 작성 | 공공 양식 연결, 사실 필드 입력 보조, 사용자 또는 전문가의 최종 작성·확인 |
| 민사 재판부가 사기 사실을 즉시 인지 | 형사절차 관련 자료를 사용자가 민사 청구 자료로 정리할 수 있도록 지원 |
| 원클릭 민사 절차 전환 | 기존 사건 데이터와 증거를 유지한 채 민사 준비 단계로 이동 |
| 강제집행 자동 연동 | 재산명시·조회·압류·추심에 필요한 절차와 체크리스트 제공 |
| 승소 후 돈 회수 | 집행권원 확보 후 별도의 강제집행과 채무자 재산 확인 필요 |

## 7. 기존 발표에서 축소하거나 이동할 내용

- `100,539건` 통계: 별도 슬라이드에서 문제 배경의 보조 수치로 축소
- 해외 서비스 비교: 본 발표에서 제외하고 질의응답용 부록으로 이동
- SHA-256·W3C PROV-O·BagIt 상세: 증거 정리 슬라이드의 발표자 노트로 이동
- PIPA 수명주기 상세: 안전장치 슬라이드의 보조 내용으로 이동
- 7대 명시적 부인 사항: 발표자 노트 또는 부록으로 이동
- 연구팀 14인·102개 출처 설명: 마지막 슬라이드 하단의 검증 정보로 축소
- Go/No-Go 세부 지표: MVP 로드맵의 검증 조건으로 요약

## 8. 최종 톤

- **제품명보다 사용자 행동을 먼저 말한다.**
- 법률 용어를 설명할 때마다 해당 용어가 제품 화면에서 어떤 기능으로 나타나는지 연결한다.
- “자동화”보다 “재사용”, “확인”, “안내”, “추적”을 사용한다.
- 위험을 나열하는 발표가 아니라, 위험을 고려해 실제로 사용할 수 있게 다듬은 서비스 기획으로 보이게 한다.
