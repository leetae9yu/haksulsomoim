# 소액 전자상거래 사기 피해자를 위한 사용자 통제형 AI 절차 내비게이터

**부제:** 형사 신고에서 강제집행까지 절차 이탈 방지를 위한 제품 설계와 지원 범위

**작성자:** 이태규 (법률·AI 융합연구)

**기준일자:** 2026년 8월 11일

**분석 법령:** 형법, 민사소송법, 민사집행법, 소송촉진 등에 관한 특례법, 개인정보 보호법, 변호사법 등
**연구 기록:** 내부 연구 오케스트레이션 기록상 14개 member/lane, 2개 확장 조사 wave와 102개 출처 레코드를 사용했으며, 출판 감사에서 소액사건심판규칙 제1조의2를 보충 근거 S103으로 추가했다. 이 보고서에는 그중 핵심 근거를 선별했다. 이는 14명의 독립된 인간 연구자 또는 외부 동료평가를 의미하지 않는다.

---

## 핵심 명제

> 본 보고서의 출발 가설은 소액 전자상거래 선입금 사기 피해자가 형사 신고 이후 배상명령, 별도 민사절차와 강제집행 사이에서 반복 입력과 절차 확인 부담을 겪을 수 있다는 것이다 [S001, S002]. S001과 S002는 Gemini가 작성한 내부 회의록으로, 대표성 있는 피해자 조사나 절차 이탈률 측정 결과가 아니다. 따라서 “절차 단절이 핵심 곤란”이라는 명제와 이를 줄이는 제품의 효과는 아직 검증되지 않은 제품 가설로 취급한다.

## 제품 요약

서비스의 사용자 여정은 네 단계로 구성된다.

1. **접수·추적:** 피해 사실과 증거를 한 번 입력한다. 사용자가 붙여넣은 공식 통지에서 사건번호·기관·일정을 추출해 원문과 나란히 보여주고, 사용자가 직접 확인한다.
2. **증거·서류 준비:** 원본과 파생 데이터를 분리하여 보존한다. OCR 추출 결과를 사용자가 검토·승인한 뒤 증거 목록과 공공 서식 준비 자료를 구성한다.
3. **배상명령·별도 민사 준비:** 형사재판이 진행 중이면 배상명령 준비 경로를, 별도 민사 절차가 필요하면 지급명령·소액소송 준비 경로를 제시한다. 전환은 법률 절차의 자동 이관이 아니라, 확인된 데이터의 재사용이다.
4. **강제집행 관리:** 집행권원 확보 이후 재산명시·조회, 압류·추심, 미회수·시효관리의 후속 절차를 상태 대시보드로 추적한다.

형사 신고 자체가 피해금의 자동 환급을 발생시키지는 않는다. 「전기통신금융사기 피해 방지 및 피해금 환급에 관한 특별법」 제2조는 재화의 공급 또는 용역의 제공 등을 가장한 행위를 전기통신금융사기 정의에서 제외하므로, 일반 물품·용역 선입금 사기는 송금이 있었다는 이유만으로 같은 법의 지급정지·환급 절차에 포함되지 않는다 [S088].

확정 지급명령, 집행력 있는 민사판결 또는 확정·가집행 가능한 배상명령을 확보해도 자동회수되는 것은 아니며, 채무자가 자발적으로 지급하지 않으면 확인된 재산에 대한 별도 강제집행이 필요할 수 있다 [S032, S035-S038, S101, S102].

제품은 경찰청 ECRM, 대법원 전자소송 또는 민간 서비스와의 직접 API 연동을 전제로 하지 않는다. 공공기관 로그인, 본인인증, 최종 제출은 사용자가 직접 수행한다. AI의 역할은 사실 정리, 추출 결과 표시, 일반 절차 안내, 공식 창구 연결, 상태 관리에 한정한다 [S089-S092].

“직접 API 연동을 전제로 하지 않는다”는 이 제품의 설계 범위 선언이지 ECRM 또는 전자소송포털에 외부 API가 존재하지 않는다는 사실 주장이나 기술적 조사 결과가 아니다. S018은 이번 감사에서 웹방화벽으로 본문을 확인하지 못했으므로 API 존재 여부, 자동제출 가능성 또는 사건별 전자제출 자격의 근거로 사용하지 않는다.

## 1. 문제와 제품 기회

### 1.1 신고 이후 다시 길을 잃는 피해자

온라인 중고거래 피해자는 ECRM에서 신고자료를 사전 작성·접수할 수 있다. 공식 안내상 원칙적으로 경찰서 출석과 진술이 필요하지만, 다수 피해 사이버사기에서 다른 피해자의 방문 진술이 시스템상 확인되는 등 안내된 예외에서는 출석 없이 수사가 진행될 수 있으며, 이 경우에도 담당 수사관이 출석을 요구할 수 있다 [S013, S014]. 내부 회의록에서는 검찰·법원의 공식 통지에 포함된 사건번호와 절차 용어를 이해하고 다음 준비사항을 판단하기 어렵다는 문제의식이 제기되었다 [S001, S002]. 이는 대표성 있는 사용자 조사로 검증된 결과가 아니라 제품 가설이다.

배상명령은 제1심 또는 제2심 공판의 변론종결 전까지 신청해야 하므로, 제품은 사용자가 공식 통지에서 현재 심급과 신청 가능 시기를 직접 확인하도록 안내한다 [S020, S045, S046]. 배상명령이 받아들여지지 않거나 별도 민사 절차가 필요한 경우에는 지급명령 또는 소액소송을 다시 검토해야 한다 [S047, S101-S103]. 지급명령은 상대방 주소와 송달이 중요하며, 상대방이 이의하면 본안 소송으로 이어질 수 있다 [S060, S061, S101].

집행권원을 확보한 뒤에도 절차는 끝나지 않는다. 채무자가 자발적으로 지급하지 않으면 재산명시, 재산조회, 채권압류 및 추심과 같은 별도 집행 절차를 검토해야 한다 [S032, S035-S038]. 법정 압류금지채권, 채무자 무자력, 회생·파산 등으로 실제 회수가 어려울 수도 있다 [S021, S043]. 제품은 이 결과를 예측하거나 보장하지 않는다. 사용자가 현재 단계와 남은 행동을 확인할 수 있게 한다.

### 1.2 가상 사용자 시나리오

29세 직장인 김민우는 중고거래 플랫폼에서 전자기기를 구매하기 위해 판매자 계좌로 45만 원을 송금했다. 판매자는 입금 직후 게시물을 삭제하고 연락을 끊었다. 민우가 가진 것은 대화 캡처, 이체확인증, 판매자 전화번호와 계좌번호뿐이다.

민우는 ECRM에 사건을 사전 접수하고 경찰서에 증거를 제출했다. 몇 달 후 검찰과 법원에서 사건 진행 문자를 받았지만, 사건번호와 절차 용어를 이해하지 못했다. 형사재판 중 배상명령을 준비할 수 있다는 사실도, 배상명령이 어려울 때 민사 지급명령을 별도로 검토해야 한다는 사실도 검색을 거듭한 뒤에야 알았다. 판결을 받으면 돈이 자동 입금될 것이라 생각했지만, 실제로는 집행권원 이후 강제집행을 별도로 진행해야 했다.

서비스는 이 여정에서 다음과 같이 작동한다.

| 시점 | 사용자의 행동 | 제품이 제공하는 도움 |
|---|---|---|
| 피해 직후 | 피해액·일시·계좌·연락처와 증거 업로드 | 사실 입력 스키마, 원본 보존, OCR 결과 확인 |
| 신고 준비 | ECRM 사전 접수와 경찰서 증거 제출 준비 | 사실표·증거목록·공식 링크 |
| 공식 통지 수신 | 검찰·법원 문구 붙여넣기 | 사건번호·기관·기일 추출 후 사용자 확인 |
| 형사재판 진행 | 배상명령 준비 여부 검토 | 신청 시기·공공 양식·필요 자료 안내 |
| 민사 경로 필요 | 지급명령·소액소송 준비 | 기존 사실과 증거를 유지한 준비 화면 전환 |
| 집행권원 확보 | 회수 절차 진행 | 재산명시·조회·압류·추심 상태 관리 |

### 1.3 통계가 말하는 것과 말하지 않는 것

경찰청 공공데이터의 구조화된 미리보기에서 100,539건은 2024년 `발생건수` 행의 **`직거래` 열** 값이다 [S041]. 이는 2024년 전체 사이버사기 발생건수가 아니며, 본 보고서가 대상으로 삼는 소액 C2C 선입금 피해자 수, 피해액, 시장 규모 또는 회수율도 의미하지 않는다.

같은 자료는 2024년에 연예빙자와 사이버투자 항목이 신설되었다고 설명하므로 2023년 이전과의 단순 시계열 비교에도 주의해야 한다. 따라서 이 수치는 경찰 통계상 직거래 사기의 배경 규모로만 제시하고 제품 수요나 효과의 근거로 사용하지 않는다.

## 2. 네 단계 제품 로드맵과 사용자 여정

본 보고서가 검증하려는 제품 가설은 반복 입력과 절차 확인 부담을 줄이는 내비게이션이 피해자의 절차 수행을 지원할 수 있다는 것이다 [S001, S002]. 제품은 구제 경로를 `접수·추적 → 증거·서류 준비 → Track A / Track B → 강제집행 관리`의 네 단계로 나누고, 각 단계에서 사용자가 확인할 사항과 이동할 공식 창구를 명시적으로 보여준다. 전 단계에서 확인한 사실과 증거는 다음 단계로 이어지지만, 실제 부담 감소와 절차 이탈 방지 효과는 사용자 연구로 검증해야 한다.

### 2.1 Stage 1 — 접수·추적

#### 단일 접수 화면

첫 단계의 목적은 피해 정보의 파편화와 중복 입력을 줄이는 것이다. 사용자는 다음 정보를 한 화면에서 한 번 입력한다.

- 거래 플랫폼명과 판매자 유형
- 결제 수단, 피해 금액, 입금 일시
- 상대방 계좌번호, 전화번호, SNS ID 등 보유 단서
- 거래 전 약속 내용과 입금 후 경과 사실
- 대화 캡처, 게시물 캡처, 이체확인증 파일
- ECRM 사전 접수, 경찰서 진술, 기소·재판 등 현재 단계

입력 화면은 각 항목을 범주별로 구분하고 필수와 선택을 명시한다. 사용자가 입력한 사실은 이후 배상명령 신청, 민사 절차 준비, 강제집행 신청에서 다시 활용되는 단일 사건 카드가 된다. 제품은 사용자가 기록한 사실을 구조화할 뿐 편취 고의나 사기죄 성립 여부를 단정하지 않는다 [S059, S075].

#### 사용자 통지 기반 사건 추적

사건 추적은 공공 전산망 자동 조회가 아니라 사용자가 직접 붙여넣은 공식 통지를 기반으로 작동한다. 경찰·검찰·법원에서 수신한 문자, 이메일 또는 우편 안내문을 화면 왼쪽에 붙여넣으면 오른쪽에 기관, 사건번호, 담당 부서·재판부, 날짜, 현재 처리 단계의 추출 후보가 표시된다.

사용자는 각 필드를 원문과 대조한 뒤 `원문과 일치`, `수정 필요`, `확인 보류` 중 하나를 선택한다. 하나라도 승인되지 않은 필드는 사건 타임라인에 반영되지 않는다. 이는 존재하지 않는 사건번호나 법원명을 생성하지 않는 제품 안전장치다.

#### 사건 상태의 내부 관리와 외부 단순화

내부적으로는 사건 분류, 증거 보존, 공공 창구 이동, 출석·송달 대기, 이의·대체 경로, 집행권원 확보, 재산 탐색, 압류·추심, 미회수·종결의 아홉 상태를 관리한다. 사용자 화면에서는 이를 `접수·추적 → 증거·서류 → 배상명령·별도 민사 준비 → 강제집행`의 네 구간으로 단순화한다. 현재 구간은 강조하고, 다음 구간은 어떤 준비가 필요한지 한 문장으로 예고한다.

### 2.2 Stage 2 — 증거·서류 준비

#### 원본과 파생 데이터의 분리

대화 캡처와 이체확인증이 시스템에 들어오면 원본 저장 영역과 OCR·메타데이터 추출 영역을 분리한다. 입고 시점의 SHA-256 해시와 증거 계보 기록은 이후 변경 탐지에 사용한다 [S063-S068]. 이 조치는 시스템 입고 이후의 무결성 관리에 한정되며, 업로드 이전 원본의 진정성이나 개별 재판에서의 증거능력을 자동으로 입증하지 않는다 [S078].

#### OCR 결과의 사용자 검토

OCR은 계좌번호, 금액, 날짜, 인명과 대화 문구를 추출한다. 증거 준비 화면은 원본 이미지의 해당 위치와 추출 텍스트를 나란히 보여준다. 사용자는 모든 핵심 필드를 원본과 대조한 뒤 직접 승인해야 다음 단계로 진행한다.

서로 다른 자료에서 날짜나 금액이 충돌하면 제품은 하나로 합치거나 임의로 선택하지 않는다. 화면에 `날짜 불일치`, `금액 미확인` 상태를 표시하고, 추가 확인 전까지 미확인으로 유지한다.

#### 증거 패킷

사용자 검토를 마친 결과는 다음 다섯 요소로 구성한다.

1. 원본 파일 목록과 파일별 식별 정보
2. 사용자가 확인한 OCR 텍스트
3. 입금과 대화의 시간순 사실표
4. 불일치·미확인 항목
5. ECRM 또는 법원 제출 준비용 사본

제품은 완성된 개별 고소장·소장·청구취지를 자율 작성하지 않는다. 대법원 B3002 배상명령 신청서 등 공공 양식과 일반 작성 안내를 연결하고, 사용자가 확인한 사실 필드를 해당 항목에 맞는 준비 자료로 정리한다 [S086, S089-S092]. 문서의 최종 작성, 검토와 제출은 사용자 또는 자격 있는 전문가가 수행한다.

### 2.3 Stage 3 — Track A와 Track B

Stage 3는 형사재판 진행 여부와 사용자의 경로 선택에 따라 두 트랙으로 나뉜다. 사용자는 상황 변화에 따라 준비 경로를 바꿀 수 있지만, 제품이 법률 절차를 자동 전환하지는 않는다.

#### Track A: 배상명령 준비 경로

형법상 사기죄 등 소송촉진 등에 관한 특례법 제25조의 대상 범죄에 관한 제1심 또는 제2심 형사공판이 계속 중이면 피해자는 그 심급의 변론 종결 전까지 배상명령을 신청할 수 있다. 신청 대상은 범죄행위로 인한 직접적인 물적 피해, 치료비 손해, 위자료 또는 피고인과 합의된 손해배상액이며, 같은 피해에 관한 손해배상청구가 다른 법원에 계속 중이면 중복 신청할 수 없다 [S045, S046].

피해자의 성명·주소나 피해금액이 불명확하거나, 피고인의 책임 유무·범위가 명백하지 않거나, 공판을 현저히 지연시킬 우려가 있거나 형사절차에서 명령하는 것이 타당하지 않으면 법원은 배상명령을 하여서는 안 된다. 부적법하거나 이유 없거나 배상명령이 타당하지 않은 신청은 법원이 **각하**하며, 신청인은 각하 또는 일부 인용에 불복하거나 동일한 배상신청을 다시 할 수 없다. 인용되지 않은 부분의 별도 민사청구 가능 여부는 중복청구 제한을 확인하여 판단한다 [S045-S047, S102].

Track A 화면은 다음 정보를 한 곳에 배치한다.

- 공식 통지에서 확인한 재판 단계
- 배상명령 신청 가능 시기와 확인 항목
- 배상명령신청서의 전산양식 번호 B3002와 최신 양식 검색 안내 [S086, S087]
- Stage 1에서 확인한 피해액·송금일·사건번호
- Stage 2에서 구성한 증거 패킷 미리보기

대법원 「배상신청에 관한 예규」 제3조는 배상명령신청서의 전산양식 번호가 B3002임을 확인한다 [S086]. 그러나 S086 URL은 양식 다운로드 링크가 아니라 예규 XML이다. 제품은 전자소송포털 양식모음에서 `배상명령신청서`를 다시 검색하도록 안내하고, 사건별 전자제출 가능 여부와 종이·우편 접수 경로를 확인하게 한다 [S086, S087]. 제품이 직접 제출하거나 제출 가능 사건을 자동 확정하지 않는다. 배상신청이 각하되거나 별도 민사청구가 필요한 경우에는 중복청구 제한을 확인하며 Track B 준비 경로를 안내한다 [S046, S047, S102].

#### Track B: 지급명령·소액소송 준비 경로

형사재판과 별개로 민사 절차가 필요하거나 배상명령이 어려운 경우에는 지급명령과 소액소송을 검토한다 [S047, S101-S103]. Track B 화면은 두 경로의 차이를 일반 정보로 비교 표시한다.

지급명령은 일정한 금액의 금전·대체물 또는 유가증권 지급청구에 이용할 수 있지만, 대한민국에서 공시송달 외의 방법으로 송달할 수 있어야 한다. 공시송달만 가능하거나 국외송달이 필요하면 법원이 사건을 소송절차에 부칠 수 있다. 채무자가 지급명령을 송달받은 날부터 2주 이내에 적법하게 이의하면 그 범위에서 지급명령은 효력을 잃고, 지급명령을 신청한 때에 소가 제기된 것으로 본다. 이의가 없거나 이의가 취하·각하되어 확정된 지급명령만 확정판결과 같은 효력을 가진다 [S101].

소액사건은 제소 당시 소송목적의 값이 3,000만 원을 초과하지 않는 금전·대체물 또는 유가증권의 일정 수량 지급을 목적으로 하는 제1심 민사사건이다 [S103]. 제품은 주소·송달·관할과 비용 정보를 제공하되 지급명령 또는 소액사건 적용 여부를 자동 확정하지 않는다 [S060, S061, S084, S101, S103].

Track B 화면에도 Stage 1·2에서 확인한 피해 사실과 증거 패킷을 표시한다. 사용자는 민사 절차에 필요한 상대방 주소, 송달 방법, 청구 항목을 추가로 보완한다.

#### 데이터 재사용 피벗

`Track B로 전환` 또는 `Track A로 전환` 버튼은 법률 절차의 자동 전환을 의미하지 않는다. 버튼을 누르면 확인된 피해 사실, 상대방 단서, 이체 내역, 증거 패킷을 유지한 채 해당 준비 화면으로 이동한다. 화면 상단에는 `기존 확인 데이터 재사용 중` 상태를 표시한다.

이 설계의 핵심은 소송 자동화가 아니라 재입력 부담의 감소다. 각 공공 절차의 최종 판단과 제출은 사용자에게 남긴다.

### 2.4 Stage 4 — 강제집행 관리

확정 지급명령, 집행력 있는 민사판결, 확정되었거나 가집행선고가 있는 배상명령 등 집행 가능한 집행권원을 확보해도 피해금이 자동 지급되는 것은 아니다 [S101, S102]. 다음 절차들은 모든 사건에서 반드시 차례대로 거치는 순서가 아니라, 집행권원의 종류와 확인된 재산에 따라 선택하는 조건부 경로다. 이미 압류할 재산과 제3채무자를 알고 있다면 재산명시를 거치지 않고 해당 재산에 대한 집행을 검토할 수 있다.

1. **집행권원 확인:** 집행력과 확정·가집행 여부, 정본, 송달증명 및 집행문 필요 여부를 집행권원별로 확인한다. 확정 또는 가집행 가능한 배상명령이 기재된 유죄판결 정본은 별도 집행문 없이 집행할 수 있다 [S086, S102].
2. **재산명시:** 금전지급 집행권원으로 강제집행을 개시할 수 있는 채권자가 신청할 수 있으나, 가집행선고부 판결 등 민사집행법 제61조 단서의 집행권원은 제외된다. 신청에는 집행력 있는 정본과 집행개시 필요 문서를 첨부한다 [S032].
3. **재산조회:** 재산명시절차에서 주소보정이 불가능했던 경우, 제출된 재산으로 채권 만족이 부족한 경우 또는 법정 불응·허위목록 사유가 있는 경우에만 신청할 수 있다. 조회기관을 특정하고 비용을 예납해야 한다 [S035].
4. **채권압류·추심:** 채무자의 제3채무자에 대한 채권을 특정하여 법원의 압류명령을 받아야 하며, 금전채권 압류는 제3채무자에게 송달될 때 효력이 발생한다. 추심명령이 있어야 압류채권자가 대위절차 없이 추심할 수 있다 [S036-S038].
5. **회수 제한·시효 관리:** 무자력, 회생·파산, 압류금지채권과 생계비계좌 등으로 전부 회수하지 못할 수 있다. 압류금지 범위는 법률·시행령과 채무자의 상황에 따라 달라지므로 고정 금액을 표시하지 않는다 [S021, S043, S044].

채무불이행자명부 등재는 직접 회수수단이 아니다. 금전지급 집행권원이 확정·작성된 뒤 6개월이 지나도록 이행하지 않은 경우 등 민사집행법 제70조의 요건과 관할·소명 요건을 별도로 확인해야 한다 [S003, S004]. 제품은 채무자 재산을 자동 조회하거나 압류하지 않으며 회수 가능성이나 예상 회수 금액을 표시하지 않는다.

## 3. 핵심 기능과 시스템 설계

본 장은 제품의 핵심 기능을 시스템 설계 관점에서 설명한다. 각 기능은 사용자가 직접 통제하는 것을 전제로 하며, 법률 판단의 자동화나 공공 전산망과의 직접 연동을 전제로 하지 않는다.

### 3.1 메시지 분석기

경찰·검찰·법원의 통지에는 사건번호, 기관, 재판부, 기일과 처리 단계 등 다음 행동을 결정하는 정보가 포함된다. 메시지 분석기는 원문과 추출 결과를 분리한 대조 화면으로 설계한다.

화면 왼쪽에는 사용자가 붙여넣은 공식 통지 원문을 그대로 표시하고, 오른쪽에는 기관명, 사건번호, 담당 부서 또는 재판부, 날짜와 현재 단계의 후보 필드를 나란히 배치한다. 각 필드에는 `원문과 일치`, `수정 필요`, `확인 보류` 선택을 제공한다.

필드는 사용자가 명시적으로 승인하기 전까지 `미확인` 상태로 유지된다. 미확인 데이터가 남아 있으면 다음 단계 진행을 차단한다. 승인된 필드만 사건 타임라인과 배상명령·민사 준비 화면에서 참조한다.

이 기능은 KICS, 대법원 전자소송 또는 검찰 시스템에 접속해 정보를 조회하지 않는다. 이는 외부 API의 존재 여부에 관한 사실 주장이 아니라 본 제품의 설계 범위다. 사용자가 가진 통지 내용만 처리하고, 원문에 없는 사건번호, 법원명, 재판부 또는 법조문을 생성하지 않는다.

### 3.2 증거 Dossier: 원본과 파생 데이터의 분리

사건 증거로 쓰이는 대화 캡처, 이체확인증과 게시물 갈무리는 원본 그대로 보존되어야 한다. 동시에 사용자는 이 자료에서 계좌번호, 금액, 날짜와 대화 문구를 추출해 구조화해야 한다. 증거 Dossier는 이 두 과정을 분리한다.

| 레이어 | 보관 내용 | 생성 시점 | 수정 정책 |
|---|---|---|---|
| 원본 | 업로드 파일, 파일명, 크기, MIME 유형, SHA-256 해시 | 파일 입고 시 | 생성 이후 수정 불가 |
| 추출 | OCR 텍스트, 날짜·금액·계좌·인명 후보 | 원본 기반 처리 시 | 사용자 교정 후 확정 |
| 사실표 | 시간순 사건 경과, 자료 간 연결 관계 | 사용자 승인 후 | 충돌·미확인 상태 유지 가능 |
| 출력 | 증거목록, 사실표, 제출 준비용 사본 | 내보내기 요청 시 | 다운로드 전 최종 확인 |

원본 레이어는 시스템 입고 시점의 파일을 변경하지 않는다. OCR 결과는 원본 이미지의 해당 영역과 함께 표시한다. 서로 다른 자료에서 날짜나 금액이 충돌하면 하나로 병합하거나 임의로 선택하지 않고 충돌 상태로 유지한다.

이 구조는 자료의 체계적 관리를 돕는 것이며, 원본의 진정성이나 법정 증거능력을 자동으로 확보하는 것이 아니다 [S078]. 증거 채택 여부는 각 재판의 심리에 따라 법원이 판단한다.

### 3.3 입고 이후 해시와 계보 관리의 범위

시스템은 파일 입고 시 SHA-256 값을 계산하고 이후 동일한 바이트열인지 비교하는 데 사용할 수 있다 [S065]. 이 값은 입고 이후 변경 탐지를 지원하지만, 파일의 작성자·사건 관련성·입고 전 진정성을 증명하지 않는다.

일반적인 서버 수신시각이나 데이터베이스 시각은 운영 메타데이터일 뿐 RFC 3161 타임스탬프가 아니다. RFC 3161을 구현하려면 신뢰할 수 있는 TSA에 메시지 임프린트를 제출하고 서명된 time-stamp token과 검증자료를 보존해야 한다. 그 토큰도 해당 임프린트가 `genTime` 이전에 존재했다는 점을 지원할 뿐 파일 생성시각, 사건 발생시각 또는 “해시 생성시각” 자체를 증명하지 않는다 [S066].

PROV-O는 변환·검토 관계를 표현하는 데이터 모델이고, BagIt은 manifest와 payload의 일치 여부를 검사하는 포장 형식이다. 어느 규격도 단독으로 내용의 진실성, 작성자 또는 법적 증거능력을 보장하지 않는다 [S067, S068]. NIST와 SWGDE 자료는 계보 관리의 참고 기준으로 활용한다 [S063, S064].

이 메커니즘은 **시스템 입고 이후**의 변경 탐지와 계보 추적에 한정된다.

- 업로드된 파일이 실제 사건 기록인지, 사전에 위변조되지 않았는지는 판단하지 않는다.
- 해시와 계보 기록이 법정 증거능력을 보장하지 않는다 [S078].
- EXIF 또는 캡처 시각이 실제 원본 생성 시점과 일치하는지 자동으로 확인하지 않는다.

### 3.4 공식 공공사이트 Handoff

제품은 ECRM [S013, S014], 대법원 전자소송 [S018], 소비자24 [S052], 대한법률구조공단 [S030] 등 공식 사이트를 상황에 맞게 연결한다. Handoff 화면에는 기관명과 목적, 준비 자료, 제출 전 확인 항목, 로그인·본인인증·최종 제출을 사용자가 수행한다는 고지를 함께 보여준다.

공공 사이트의 URL, 서식과 접수 절차는 변경될 수 있으므로 링크와 안내에 출처와 확인 기준일을 표시한다. Handoff는 데이터를 공공 시스템에 자동 전송하는 기능이 아니다. 공공·민간 서비스와 직접 데이터를 송수신하지 않으며, 최종 제출과 비용 결제는 사용자 또는 자격 있는 전문가가 직접 수행한다.

### 3.5 개인정보 보호법 수명주기

대화·계좌·연락처·사건 문서에는 개인을 알아볼 수 있는 정보가 포함될 수 있으며, 해당하는 범위에서 개인정보 보호법이 적용된다 [S093]. 서비스는 정보주체와 항목별로 제15조 등 수집·이용 근거를 먼저 확정하고, 목적에 필요한 최소한만 처리해야 한다. 민감정보 또는 고유식별정보가 포함되면 별도 요건도 확인한다.

외부 OCR 등 개인정보 처리위탁에는 제26조에 따른 문서화, 위탁업무와 수탁자 공개, 재위탁 동의 및 감독이 필요하다. **처리위탁이라는 이유만으로 정보주체 동의가 항상 필요한 것은 아니다.**

국외 처리위탁·보관은 제28조의8 제1항 각 호 중 하나의 근거가 있을 때만 가능하다. 별도 동의를 근거로 하면 같은 조 제2항의 사항을 미리 알려야 하고, 계약 이행에 필요한 위탁·보관 근거를 사용하면 처리방침 공개 또는 법정 방법의 통지 등 해당 요건과 보호조치를 충족해야 한다. 국외이전에는 언제나 사전 동의가 필요하다고 안내해서는 안 된다.

보유기간이 지나거나 처리목적을 달성하는 등 개인정보가 불필요해지면 다른 법령의 보존의무가 없는 한 지체 없이 파기하고, 보존해야 하는 정보는 분리 저장·관리한다 [S093]. 삭제 요청은 즉시 파기와 동일하지 않다. 제36조에 따라 요청 대상과 법정 예외를 조사하고 정정·삭제 등 필요한 조치를 한 뒤 결과를 통지한다.

사건 자료는 모델 학습에 사용하지 않는 것을 제품정책으로 명시한다. 이는 기존 처리가 자동으로 적법하다는 의미가 아니며, 운영자는 별도의 처리근거·안전조치·처리방침을 갖춰야 한다.

## 4. 법적·운영적 안전장치

### 4.1 제품 기능으로 구현하는 법적 경계

변호사법 제109조 제1호는 변호사가 아닌 자가 금품·향응 또는 그 밖의 이익을 받거나 받을 것을 약속하고 또는 제3자에게 이를 공여하게 하거나 공여하게 할 것을 약속하고 일반 법률사건 등에 관하여 법률상담, 대리, 화해, 법률관계 문서 작성 또는 그 밖의 법률사무를 취급·알선하는 행위를 처벌한다 [S089]. 서비스가 명목상 사용자의 자기작성 형식을 취하는지보다 실제로 사건처리를 지배·대리했는지, 법률판단과 제출문서를 누가 작성했는지, 대가와 변호사의 실질적 감독이 있었는지가 중요하다 [S090-S092].

본 연구가 2026년 8월 11일까지 확인한 공개 1차 자료에서는 이 제품 유형에 관한 AI 전용 구속 판례나 공개된 safe harbor를 찾지 못했다. 따라서 아래 범위는 적법성이 확정된 “허용 영역”이 아니라 위험을 낮추기 위한 보수적 제품정책이며, 실제 운영형태에 대한 별도 법률검토가 필요하다.

| 영역 | 제품 동작 |
|---|---|
| **보수적 설계 범위(적법성 확정 아님)** | 사용자 입력 사실의 기계적 구조화, 원본·OCR 대조, 일반 절차와 공공 양식 안내 |
| **사용자 확인 필수** | 피해액·날짜·계좌·성명 승인, Track 선택, 내보내기 문서 검토 |
| **금지** | 편취 고의·사기 성립 단정, 승소·회수 예측, 개별 완성 법률서면 작성, 공공기관 대리 제출, 원문에 없는 정보 생성 |

### 4.2 개인정보 수명주기의 제품 반영

대화·계좌·연락처·사건 문서에 개인을 알아볼 수 있는 정보가 포함되는 범위에서 개인정보 보호법이 적용된다 [S093]. 서비스는 정보주체와 항목별 수집·이용 근거를 먼저 확정하고 목적에 필요한 최소한만 처리한다. 외부 OCR 처리위탁에는 제26조에 따른 문서화, 공개와 감독을 적용하되 처리위탁이라는 이유만으로 동의가 항상 필요하다고 단정하지 않는다. 국외 처리위탁·보관은 제28조의8의 근거와 해당 고지·동의·처리방침·보호조치 요건을 구분해 충족한다.

보유기간 경과 또는 목적 달성으로 정보가 불필요해지면 법정 보존의무가 없는 한 지체 없이 파기하고, 보존 정보는 분리 관리한다. 삭제 요청은 즉시 파기와 동일하지 않으며 제36조의 대상과 예외를 확인한 뒤 필요한 조치와 결과 통지를 수행한다. 사건 자료를 모델 학습에 사용하지 않는 것은 별도의 제품정책이고, 그 정책만으로 기존 처리가 자동으로 적법해지는 것은 아니다.

### 4.3 여섯 가지 불변 규칙

1. 원문에 없는 사건번호, 법원명, 재판부와 법조문을 생성하지 않는다.
2. 피해액, 날짜, 계좌번호와 성명을 사용자 확인 없이 수정하지 않는다.
3. OCR 신뢰도와 무관하게 핵심 필드는 사용자가 직접 승인한다.
4. 미확인·충돌 데이터를 숨기거나 임의로 합치지 않는다.
5. 법률 결과, 회수 효과와 시효의 법률효과를 자동 확정하지 않는다 [S044].
6. 공공기관 최종 제출, 비용 결제와 본인인증은 사용자가 수행한다.

이 안전장치는 제품 설계의 위험 통제 정책이며 개별 사건의 적법성 또는 규제기관의 최종 판단을 대신하지 않는다. 실제 서비스 운영에는 법률 전문가의 지속적인 검토가 필요하다 [S078, S089-S093].

## 5. 단계별 구현 및 검증 계획

구현은 법적 위험이 낮고 사용자 가치가 명확한 기능부터 시작한다. 각 단계는 이전 단계 검증을 마친 뒤에만 다음 단계로 진입한다.

### Phase 0 — 경계와 데이터 계약

- 보수적 설계 범위·사용자 확인·금지 기능을 제품 요구사항으로 고정
- Intake 스키마, 사건 상태 모델과 Track 분기 조건 정의
- 개인정보 처리 흐름, 보존·파기와 접근권한 확정
- 법령·공공 서식의 버전과 출처 관리 방식 결정

### Phase 1 — 증거 정리 MVP

- 원본 파일과 식별 정보, 입고 시점 SHA-256 기록 [S063-S065]
- 한국어 OCR과 핵심 필드 추출
- 원본·추출 텍스트 대조와 사용자 승인
- 시간순 사실표, 증거목록과 승인된 PDF 사본 출력

검증의 중심은 OCR 정확도만이 아니라 원본 보존과 사용자 확인 절차의 완전성이다.

### Phase 2 — 사건 추적과 트랙 전환

- 공식 통지 붙여넣기와 사건 필드 추출
- 원문 대조와 사용자 승인
- 사건 단계 타임라인
- Track A 배상명령 준비와 Track B 지급명령·소액소송 준비 [S020, S045-S047, S060, S061, S084, S101-S103]
- 데이터 재사용 피벗
- ECRM, 전자소송과 법률구조공단 Handoff [S013, S018, S030]

### Phase 3 — 강제집행 후속 관리

강제집행 절차를 일률적인 순서로 강제하지 않고 집행권원의 종류, 확인된 재산과 각 법정 요건에 따라 조건부 경로로 제공한다.

- 집행력과 확정·가집행 여부, 정본·송달증명·집행문 필요 여부 확인 [S032, S086, S101, S102]
- 민사집행법 제61조 단서와 첨부문서를 반영한 재산명시 안내 [S032]
- 재산명시 결과 부족, 불응·허위목록 등 제74조 요건을 충족할 때의 재산조회 안내 [S035]
- 제3채무자와 대상 채권 특정, 압류명령 송달, 추심명령의 조건별 상태 관리 [S036-S038]
- 무자력, 압류금지채권, 회생·파산과 시효 상태 [S021, S043, S044]

### Phase 4 — 전문가 검증과 제한된 시범 운영

- 법률 전문가의 기능 경계 검토
- 피해자 사용성 검토
- 법률 오안내·누락 사례 점검
- OCR·필드 추출 오류 분석
- 개인정보 흐름, 접근통제와 파기 절차 감사

### 출시 전 Go/No-Go

아래 조건은 달성 결과가 아니라 출시 전에 검증할 조건이다. 하나라도 미충족하면 출시를 보류한다.

| 조건 | 측정 방식 |
|---|---|
| 원본과 내보내기 패킷의 파일 식별·해시 매핑이 전수 일치 | 자동 무결성 검사 |
| 핵심 필드가 사용자 승인 없이 확정되지 않음 | 상태 전환 로그 감사 |
| 사기 성립·승소·회수 가능성을 단정하는 출력 0건 | 출력 규칙 전수 검사 |
| 자동 제출·직접 API 연동으로 오인되는 기능과 문구 0건 | UI·도움말 전수 검토 |
| 보존 예외를 반영한 파기 절차 작동 | 삭제 요청 처리 시험 |

본 연구는 시장 수요, 지불 의사, 절차 이탈 감소와 회수율 개선을 실증하지 않았다. 제안 기능은 연구 가설이며 실제 유용성은 사용자 연구와 제한된 시범 운영으로 검증해야 한다.

## 6. 결론

본 보고서가 검증하려는 제품 가설은 반복 입력과 절차 확인 부담을 줄이는 내비게이션이 피해자의 절차 수행을 지원할 수 있다는 것이다. 형사 신고, 배상명령, 별도 민사 절차와 강제집행은 서로 다른 요건과 공식 창구를 가지므로 제품은 이를 하나의 자동 절차로 합치지 않는다 [S032, S035-S038, S045-S047, S084, S101-S103].

사용자 통제형 AI 내비게이터는 한 번 입력한 사건 정보와 증거를 이후 단계에서 재사용하고, 공식 통지는 원문과 추출 결과를 나란히 제시해 사용자가 직접 확인하게 한다. 형사·민사 준비 경로의 전환은 법률 절차의 자동 이관이 아니라 확인된 데이터의 재사용으로 구현한다 [S020, S045-S047, S060, S061, S084, S101-S103]. 집행권원 확보 이후에도 강제집행을 별도 상태로 관리한다 [S003, S004, S032, S035-S038, S043, S044, S101, S102].

확인·재사용·안내·추적을 중심으로 한 제품 설계는 자동 소송과 구별되며, 법률 판단과 최종 제출은 사용자와 자격 있는 전문가에게 남는다 [S089-S092]. 개인정보 수명주기와 기능 경계는 정책 문서에만 두지 않고 제품 구조에 반영한다 [S093].

본 연구는 실제 절차 이탈 감소, 처리기간 단축, 승소 또는 회수율 개선을 입증하지 않았다. 제안된 기능은 연구 가설이며, 가장 안전한 증거 정리 기능부터 단계적으로 검증해야 한다. 법적 경계와 개인정보 요구사항은 법령과 관할기관 해석에 따라 달라질 수 있으므로 지속적인 검토가 필요하다 [S078, S089-S093].
