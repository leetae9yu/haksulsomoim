# Evidence intake

Scope: a domestic bank-transfer fraud case of KRW 30,000,000 or less handled by an individual without counsel. This checklist sets work order. It guarantees no legal outcome.

## Facts to collect, in order

1. Transfer: date and time, amount, receiving bank, account number as the user saw it, account holder name as displayed, transfer memo.
2. Counterparty: display name, platform ID, phone, email, account numbers, each tagged with where the user saw it.
3. Deal: platform, listing URL or capture, promised goods or service, agreed price and terms.
4. Timeline: first contact, agreement, payment, first missed promise, each follow-up, last contact.
5. Prior actions: bank freeze or report request, police or prosecution complaint, platform report, legal consultation, with dates and reference numbers.

## Evidence inventory

Preserve originals locally, unedited:

- bank transfer confirmation or 계좌이체 확인증;
- full conversation exports or screenshots, not excerpts;
- listing, product, and profile captures;
- complaint and consultation records with reference numbers;
- receipts for any fee already paid.

Record each item on the case card with a local path, capture date, and who captured it. Do not rename or edit originals. Work on copies.

## Reliability rules

- OCR output is a draft. The user must compare it against the original before any extracted value becomes a case fact.
- A screenshot of a screenshot is weaker than the platform original. Note the capture chain.
- Memory-based facts are marked as recollection until a document confirms them.
- Before planning next steps, check recovery likelihood, whether the counterparty can be identified, and expected cost and time. Say so plainly if the expected cost outweighs likely recovery.

## Boundaries during intake

Never ask the user to attach raw evidence in chat. Ask the user to describe or transcribe the specific item needed. Apply `privacy-boundary.md` to every fact recorded.
